# Direct reported-window comparison

Status: active — quarterly slice delivered; exact sec_readonly admission correction awaits independent review.

## Objective and boundaries

For one company, compare 2–4 distinct reported 75–105-day windows using the existing eleven comparison metrics, their reasons, units and provenance. Identify windows by exact start/end dates; do not infer fiscal-quarter labels, generate Q4, subtract YTD values, rank, convert currencies or promise complete coverage. Window discovery is the union of all eleven metric anchors, not revenue-first discovery. Preserve overlapping or same-end/different-start windows separately and warn users that accounting and period comparability remain unverified.

The first slice deliberately supports only the configuration where the four existing financial authorization/evidence registries are empty. Detect active or changed registries and fail closed with a clear unsupported-configuration state; this does not establish parity for active authorizations. Use the existing bounded Insights complete-company inventory and canonical financial engine, not selected-window SQL or a second calculator. Preserve annual API behavior. Source fiscal annotations remain source metadata, not inferred selection labels.

Limits inherited from Insights include 10,000 facts, 8 MiB input, 256 candidate rows per metric/window, 256 discovered windows, 2 million work visits, 4 MiB encoded output and a 20-second cooperative deadline. These are logical checks, not a native memory or hard-deadline guarantee. Selection is 2–4 exact windows with a single publication pin; no partial result on mismatch, overflow or malformed inputs. No production DB writes, acquisition, credentials, .env inspection, installs or provider calls are authorized by this plan.

## Architecture and decisions

The additive `GET /companies/{ticker}/financials/quarters` uses the existing Insights read-only session, resource budget and financial engine. Zero `period` parameters discover windows; 2–4 distinct `period=start,end` parameters request one comparison. A verified `X-FinLens-Data-Version` is required for both. The client rejects malformed identities, windows, metric fields, evidence and publication changes before displaying the grid. The grid uses the existing source disclosure and horizontal focus-reveal behavior. The API projects inferred fiscal labels out of period presentation only after calculation; original source annotations remain source annotations.

Each metric uses its own canonical anchor for a shared date pair. In particular the existing YoY calculation uses its revenue anchor instead of whichever other metric happened to be visited last. The full company inventory remains available to the engine, including prior-year facts and bank-classification inputs.
