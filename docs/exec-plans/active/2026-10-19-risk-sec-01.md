## Verified API compatibility

Static source inspection only: main.py VersionedRoute wraps the context route.
The selected context handler enters freshness_service.read_session. With the
captured X-FinLens-Data-Version request header, read_session either verifies the
stored nonnegative version (including 0) or raises DATA_VERSION_CHANGED. Missing
metadata cannot yield pinned success. VersionedRoute writes the verified version
as X-FinLens-Data-Version and Cache-Control: no-store. No live request was made.

sec_client.build_filing_url defines the existing source shape as
https://www.sec.gov/Archives/edgar/data/{unpadded CIK}/{undashed accession}/{accession}-index.html.
rag_context_service returns stored chunk.sec_url; validate_chunks checks that exact
builder shape. Risk-only validation uses that evidenced shape and never constructs
a replacement clickable source. Selected citations may omit CIK; no CIK is added.
Company-wide validation is deeper than selected publication membership/bounded
inventory checks. This feature does not strengthen the backend eligibility contract.

## Decisions

- Six guides use the approved short queries; none classifies issuer risk.
- Topic preparation clears obsolete work, focuses the editor and never fetches.
- Native purpose controls preserve general research as the default.
- Risk dispatch makes one context request, with mandatory captured version.
- Risk results require response/source consistency before rendering attribution.
  Insufficient evidence is separate from malformed/unavailable evidence.
- Render-time request ownership protects callbacks before passive cleanup commits.
- Reuse evidence cards with risk copy and disabled AI/tone actions in risk mode.

## Implemented behavior

Native Research purpose defaults to General research. Risk-topic exploration has
the six approved immutable guides. Selecting a topic prepares the editor; Use
risk topic also focuses it. Neither fetches. Query edits use a custom-search label
unless they exactly match a guide. Purpose/topic edits invalidate pending work.

Risk submission requires searchable evidence and a verified pin, makes exactly one
existing context request, and never requests direct answers, AI or tone. Returned
candidate passages reuse existing cards/disclosures/links in backend order. General
research preserves its previous direct-answer/evidence independence and optional
AI/tone. A captured owner key plus monotonic scopes and cancellation guard risk
callbacks and rendered results across changes, including before passive cleanup.

getFilingContext has one optional final requirePublishedVersion argument defaulting
to false. Risk passes true; existing calls retain their behavior. Company-wide
continues its mandatory header/body pin checks. New risk-only pure consistency
checks validate schema, source IDs, CIK binding, canonical server-returned filing
URLs, actual dates/forms, offsets, bounded scores, source framing and metadata.
Selected citation CIK may be absent and is never synthesized. Validation does not
authenticate a database manifest or certify semantic disclosure relevance.

Valid empty evidence is insufficient, never no-risk. Missing pins/readiness,
filing-list failures, malformed responses, stale versions, pending/oversized scopes,
encoder/database/network/deadline failures remain unavailable/error states. Existing
freshness reconciliation is retained; search retry is explicit without fallback.
