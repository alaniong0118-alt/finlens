## Implemented behavior

The new section accepts two distinct catalog ticker/CIK pairs and one immutable
guided topic. AAPL/COST are preferred only when both valid catalog identities exist;
readiness is never inferred from selection/catalog membership. The sole scope is
company-wide published filings. Each issuer independently verifies freshness then
performs one pinned context GET. No waiting for the peer's freshness or result.

The comparison-local runtime reserves submission synchronously, freezes captured
identities, binds callbacks to run/column/controller ownership and checks the live
selection before every operation. Topic/issuer edits invalidate synchronously;
render-time owner checks cover catalog changes before passive cleanup. Each changed
callback is guarded before invalidating its own pin. Cleanup never auto-submits.
One performance.now-based 30-second deadline covers both chains and validation;
checks before dispatch and commitment supplement the owned timer. Completed columns
survive cancellation/deadline/peer failure; unfinished columns settle and abort.

All context responses pass unchanged transport checks and validateRiskEvidence,
then exact company-name/CIK and evidence_version-to-captured-freshness equality.
No source data renders until the entire issuer response validates. Empty eligible
inventory, insufficient topic matches, unverified responses and partial results
remain distinct. Data/evidence versions are labelled company-level; reporting-period
alignment and complete source coverage are explicitly unverified. Exclusion counts
are not complete pending/unpublished totals. Source ranks remain issuer-local.

EvidenceResults only changes its fixed container ID to React useId. Three concurrent
instances retain independent expansion controls; risk=true keeps tone suppressed.
The new panel stacks at mobile width, names issuer regions, announces statuses and
restores submit focus after cancellation. No finance-comparison behavior changed.

### Root cause and correction

The previous boolean transfer flag was set only by explicit Cancel clicks. Async
success, failure/partial settlement and the total deadline removed a focused Cancel
without setting it. The unconditional explicit flag could also steal focus if a
programmatic cancellation happened after the user moved to another control.

Cancel's callback ref now observes its connected node and actual document focus
at detachment, before DOM removal. It records a transfer only for the attached
button's CURRENT owner/generation when that same run is settled. A layout effect
consumes the token once after mutation: exact owner/generation must still match,
the target must be connected and enabled in the same document, and focus must be
on the body after removal. If another control owns focus, no transfer occurs.
Selection edits and lifecycle cleanup clear transfer intent. No focus timeout,
global listener, request, retry, automatic submission or runtime-library edit.

Manual cancellation now follows this same focused-Cancel rule. The adjacent
synthetic click regression explicitly focuses Cancel first (matching keyboard/
browser activation), retaining its exact post-commit submit-focus assertion.
The test harness exposes idempotent unmount for disconnected-target regressions.
