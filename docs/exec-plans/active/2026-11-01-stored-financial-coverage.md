## Objective and scope

## Limits and architecture

Set limits before implementation: 64 discovered windows, 704 cells (64 × 11), 4,096 returned source references (selected + alternative + operand fact references, including repetition), 10,000 complete company facts, 8 MiB input, 256 candidates per metric/window, two million cooperative work visits, 4 MiB encoded output, 20-second cooperative deadline. Excess rejects the entire result; no truncation or partial completeness label. These are logical operational checks, not hard native memory/time guarantees.

Reuse the existing bounded complete-company inventory and financial engine, publication-pinned repeatable-read boundary, publication-time registry rechecks and nonnegative safe integer versions including zero. Support only the already declared empty four authorization/evidence registries; active or changed configuration denies with a clear message. Formulas and existing annual/quarter API semantics remain unchanged. Source annotations remain annotations; date-only presentation follows engine selection.

One explicit Load action makes one request for the selected annual/quarter kind. No automatic startup or selection-change requests. Company/publication/period changes, cancellation and errors hide the prior matrix; ignored-abort/late responses cannot restore it. Reuse the quarterly financial lineage and SEC path checks through a bounded shared column validator while retaining the existing quarterly selector/response constraints.
